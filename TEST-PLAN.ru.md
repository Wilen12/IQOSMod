# Проверка GitHub Releases: testing и откат

Эти действия выполняются только в отдельной копии клиента с отдельным UserData и тестовым миром. Основная установка и Stable Candidate не используются. EAC выключен штатно; защищённые серверы не используются. До загрузки мира достаточно проверить скачивание/перезапуск/откат.

## Исходный стабильный выпуск

Установите клиент из v3.0.6 в тестовую копию. `iqosupdate status` должен показывать 3.0.6, repository Wilen12/IQOSMod и channel stable. `iqosupdate check` после публикации только v3.0.6 должен завершиться без pending и без баннера обновления. Зафиксируйте исходный тестовый профиль для повторного опыта.

Пререлиз v3.0.7-test.1 должен иметь prerelease=true и три файла `iqosmod-testing.manifest.json`, `iqosmod-testing.manifest.sig`, `iqosmod-testing.zip`. Их manifest имеет Version3.0.7, Channel testing, Sequence2. Обычный канал stable его не выбирает.

## Настоящее скачивание и применение

В отдельном тестовом профиле:

```text
iqosupdate repository Wilen12/IQOSMod
iqosupdate channel testing
iqosupdate enabled on
iqosupdate check
iqosupdate status
```

Дождитесь «проверено и готово», проверьте pending. В текущем процессе версия остаётся 3.0.6. После полного закрытия и запуска этой же тестовой копии ожидаются 3.0.7, один Runtime и уведомление об успешном применении. В журнале появляется одна диагностическая строка `[IQOSMod.UpdateTest]` при инициализации. При необходимости проверьте HEETS/перезарядку и сохранение в тестовом мире. Это не изменение игровых бонусов или баланса.

## Ошибка и откат после скачивания с GitHub

Повторите скачивание 3.0.7 на втором свежем тестовом профиле 3.0.6. Не запускайте новую версию. Полностью закройте тестовую игру. Точный путь хранилища получен из `iqosupdate status`; в state.json находится pending-id.

В рамках контролируемого теста измените один байт или переместите DLL **только подготовленного pending-поколения этого отдельного профиля**, предварительно сохранив её копию вне хранилища. Не изменяйте Good, исходную 3.0.6, постоянные Bootstrap/Gate, основные Mods или пользовательские сохранения. Если не уверены в целевом пути, остановитесь: такой шаг должен выполнять разработчик по проверенному абсолютному пути.

Следующий запуск обязан отвергнуть повреждённое поколение по хешу/размеру, оставить 3.0.6 и показать сообщение о сохранении предыдущей версии. Повреждённая DLL не должна загружаться. Этот опыт проверяет откат/отказ после настоящего скачивания без публикации намеренно неисправной DLL другим пользователям.

Отдельный подписанный пакет 3.0.8 с намеренным исключением InitMod подготовлен только как локальная фикстура разработчика. Он не входит в список загрузки и не публикуется ни в stable, ни в testing. Локально он позволяет дополнительно проверить world/network gates и возврат к предыдущей здоровой 3.0.7 при следующем запуске.

## Возврат и границы результата

Переключение канала на stable само по себе не понижает установленную 3.0.7 до 3.0.6. Восстановите исходную копию только тестового профиля либо используйте новый тестовый UserData. Основную игру не изменяйте. Для реальных будущих релизов sequence должен быть больше всех уже использованных опубликованных последовательностей.

До публикации тестового Release нельзя подтвердить скачивание его assets через настоящий GitHub. Локальные подписанные фикстуры и проверка пустого реального списка Releases учитываются отдельно; успех реального скачивания должен быть зафиксирован после публикации и согласованного теста.
